# 从来源同步

项目或目录可以记住文档所在的地址，以后再把那份文档取回来。这篇说的是已经绑定的来源。一次性导入、并更新已有接口时，会多留下一些你设过的东西，那是[导入](./IMPORT_zh.md)。返回[功能说明](./FEATURES_zh.md)。

## 绑定来源

地址存在项目里，任何编辑者都能改。

- 导入时，从地址**获取**并勾选记住来源。
- 首页的新建项目或编辑项目弹窗。
- 目录设置里，给这个目录自己的文档。
- 同步弹窗里的**仅保存地址**。

**从来源同步…**在接口树顶栏的 **⋯**、命令面板和目录菜单里。弹窗先显示地址，点**获取**才去取。地址在本机或内网时会提示，因为任何编辑者都能改它。

目录来源只在这个目录里面匹配，相邻目录里的另一份服务不会碰到。项目来源看来源导入到的那个目录；导入在顶层时看整个项目。

## 预览

获取之后先不写入。弹窗说明会添加哪些、会更新哪些，以及来源里已经没有的接口。这些仍留在项目里。

文档改了名称，也算一次更新。请求或响应 Schema 的破坏性变更单独列出：移除字段、类型变化、新增必填字段。只改名称不算这种变更。确认后才更新（*0.4.1*）。

## 同步写什么

匹配方式和[再次导入](./IMPORT_zh.md#怎样算同一个接口)相同：方法相同、路径相同。文档里第一条真正改动这个接口的会被用上。打开的标签页里还没保存的内容，是这次合并的底稿。

只留下你填写的参数值，以及认证里已经填上的密钥。其余跟文档走。

留下的：

- 参数的值、表单字段的值，以及种类没变的 JSON 值。`{{模板}}` 可以占据任何值的位置。
- 认证种类没变时，已经填上的密钥：Basic 或 Digest 的用户名和密码、Bearer 令牌、API Key 的值，以及 OAuth 的 client id、client secret、用户名和密码。你的密钥是空的时候，用文档里的。
- 你自己加的断言、提取和请求设置。
- 名称在文档里没有的示例。

跟文档走的：

- 接口名称。文档给出的名称去掉空白后不是空的，就用文档的。
- 参数开着还是关着、说明（文档的说明是空的，就清掉你的）、键的写法。文档里没有的参数去掉。
- 路径参数、Query 和请求头的类型、是否必填、format 和枚举。文档里空了，这边也清掉（*0.4.1*）。
- 接口自己的说明。文档的说明是空的，也会清掉。
- 认证方式。种类变了，就整份换成文档的。种类没变时，API Key 的名字和位置，以及 OAuth 的授权方式、客户端认证、回调端口、令牌地址、授权地址、scope、audience、resource，都用文档的。
- 字段。JSON 对象的键跟文档。种类不同的值用文档的。数组按序号逐项对齐：你多出来的去掉，文档多出来的加进来。不是 JSON 的、读不成 JSON 的，或内容类型变了的请求体，用文档的。
- 变量，包括路径参数：键、顺序、开关和说明跟文档。键对得上的留下你的值。只有你有的变量去掉。
- 文档里的示例，按文档的顺序。去掉首尾空白后名称相同的，用文档的那份。
- 文档里标为导入的 Schema 检查，换掉上一次同步导入的。你自己写的检查留下，也不会挡住文档的 Schema 检查。
- 请求 Schema。文档没有时，也清掉。

结果没有变化时不写入，项目的修订号也不增加。

## 定时同步

可以在本机对信任的来源勾选**在本机定时自动同步**。间隔是 5、15、30 或 60 分钟。后台拉取，有新增或更新时按上面的规则合并，不再询问。文档没有变化时不写入。

地址被别人改掉之后，这个定时就停了。

定时自动同步，和下面的只读字段拉取，只能开一个。

## 只拉取字段说明

**在本机定时拉取字段说明**不写项目。它在内存里留一份只读缓存，按方法和路径，给手建的或还没同步的接口在“说明”标签页展示入参和出参。来源有新增或更新时会提示，再由你决定是否同步。
