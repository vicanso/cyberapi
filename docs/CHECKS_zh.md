# 检查、说明和运行

接口如何说明自己的响应、响应如何检查，以及一个目录或项目如何运行。返回[功能说明](./FEATURES_zh.md)。

## 说明

- “说明”标签页是 Markdown，可在编辑和预览之间切换。
- 列出的入参和出参包括：路径参数、Query、请求头、表单或 multipart 的每一行，以及从请求体 JSON Schema、响应体 JSON Schema 断言读出的嵌套字段。每项有类型、是否必填和说明。
- 标签页里的**请求 Schema…**和**响应 Schema…**可以手写，也可以从当前的 JSON 请求体或响应体推断。
- JSON 请求体工具栏的**生成示例**按请求 Schema 填一份请求体。请求体不符合请求 Schema 时，工具栏和发送前会提示，发送不被拦住。
- 历史菜单的**存为示例**把当前显示的响应存在接口上。在“说明”里点开看响应体。
- 目录的说明写在目录设置里。
- 说明、Schema 和示例都跟着项目走：队友看得到，AI 经 MCP 读得到，导出 Postman 和 OpenAPI 时带上（说明、请求与响应 Schema、保存的响应、响应示例）。从 Postman（包括保存的响应）、Insomnia 和 OpenAPI 导入时也会读进来。
- 服务器项目还有只读页面 `GET /v1/docs/<project-id>`（项目菜单的**在线接口文档**）。用登录会话或 `?token=cat_…` 打开。页面画出目录树、说明、字段表、示例和多语言代码片段，敏感值打码。

## 断言

不用写脚本。在“断言”标签页里，每一行对着当前显示的响应检查，边改边出结果。

- 检查的是状态码、某个响应头、JSONPath 取到的值、响应体、耗时或大小。
- 比较可以是等于、包含、匹配正则、存在、大于或小于、类型是。
- 失败时写出实际是什么。状态行显示通过了几条，点它就打开这个标签页。
- AI 助手发送这个接口时，回答里带上同样的结果。历史不记这些结果（*0.3.1*）。

## JSON Schema

一行可以检查响应体（JSON）是否符合一份 JSON Schema（*0.4.1*）。

- 在弹窗的编辑器里写。默认 draft 2020-12，写了 `$schema` 时照它。`$ref` 只指向 Schema 自身，不去网上取。
- 不符合时列出前 3 处。
- 导入 OpenAPI / Swagger 时，每个操作第一个 2xx 的 JSON 响应的 Schema 会成为这样一条，标着“来自导入”。[从来源同步](./SOURCE_zh.md)会用文档里的这些行换掉以前导入的。你自己写的检查留在旁边。改过那条导入的行之后，它就算你的：下次同步留下你的修改，同时再带回文档的那一行。手动再次导入不同：你自己的 Schema 检查代表导入的那条，导入的行就不再加入。见[导入](./IMPORT_zh.md)。
- 导出 OpenAPI 时用它作响应的 Schema，按 OpenAPI 3.0 的写法：`nullable`、布尔形式的开区间边界、把它自己的 `$defs` 展开。3.0 没有的（如 `if`）不写。
- `cyberapi-cli run` 也检查它，可以在 CI 里做契约测试。

## 用示例做检查

一行可以要求响应与接口上保存的某个示例一致：比状态码和响应体。

- JSON 按值比较。空格和键的顺序不影响结果。这一行可以列出要忽略的 JSONPath（时间戳、id），比较前从两边去掉这些位置。
- 纯文本按原文比较。这时不能填忽略路径。
- 用的是接口上的那份示例。改了示例，下次检查就按新的来。

## 运行

目录或项目菜单的**运行…**按树的顺序依次发送。

- 可设置请求间隔、失败重试次数，以及遇失败即停。
- 每个请求结束就显示它的响应和断言结果，并汇总通过和失败的数量。没有断言时，错误状态码算失败。
- 可导出 JUnit XML 或一份自包含的 HTML 报告。点一条结果即打开对应接口并显示这条响应。
- 可以给一份数据：带表头的 CSV，或 JSON 对象数组。粘贴，或在桌面版选文件。每行运行一遍，列的值用 `{{value(列名)}}` 读。
- 断言下面的**提取**从响应里取一个值（JSONPath、响应头、状态码等），同一次运行里后面的请求用 `{{value(名称)}}` 读。例如先登录，再带着 token 调后面的接口。
- 这些值只属于这次运行，不写进项目。发出的请求和平时一样记进各接口的历史。
- 当前环境标为生产环境时，开始前确认一次。

## 命令行

`cyberapi-cli run` 是不开窗口的同一次运行。怎么安装，以及 `--env`、`--env-file`、`--var`、`--data`、`--prompt`，见[安装](./INSTALL_zh.md#命令行)。

```sh
cyberapi-cli run project.json --env staging --data users.csv --junit results.xml
```

- 文件可以是 CyberAPI 自己的导出，或任何应用能导入的格式。
- 每个请求结束就打印一行。`--delay-ms`、`--retries`、`--bail` 和弹窗里的间隔、重试、遇失败即停对应。`--junit` 写 JUnit XML，`--html` 写 HTML 报告。
- 有没通过的就以非零退出码结束。

## 压测

桌面版在接口的右键菜单里有**压测…**（*0.4.1*），反复发送这一个接口。

- 1 到 50 个并发。按次数（最多 10 万次）或按时长（最多 10 分钟）。
- 边发边显示吞吐（次/秒）、错误率、平均和最快 / 最慢、P50 / P90 / P95 / P99，以及各状态码和错误各有多少。没有响应或错误状态码算失败。不检查断言。
- 变量、Cookie 和令牌在开始时读取一次。`{{uuid()}}`、`{{random(…)}}`、`{{randomString(…)}}`、`{{now(…)}}`、`{{timestamp()}}` 每次发送重新求值。
- 不跟随重定向，不应答 Digest 质询，不写入历史，也不保存响应设置的 Cookie。
- 当前环境标为生产环境时先确认。
- 网页版没有这一项。请求都经服务器转发，每个账号同时能发出的数量有限。
