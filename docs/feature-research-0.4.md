# 0.4.0 之后：还值得加的功能

> 状态：调研稿（2026-10-29）。[feature-research-0.3.md](./feature-research-0.3.md) 里定下要做的都已完成并随 0.4.0 发布；那份文档里暂缓、决定不做或没选的（A5、C1、C3、E4、G3、G5、G7、H2、H3、网页版 WebSocket、预览标签、Q2 / Q8 / Q10 等）这里不再讨论。每一项的“默认做法”是动手前替维护者定下的，都可以改；进度记在 [issue-plan.md](./issue-plan.md) 的“0.4.0 之后”。

## 1. 结论

建议做 7 项，按投入从小到大：

| 顺序 | 编号 | 功能 | 规模 | 数据模型 |
|---|---|---|---|---|
| 1 | B7 | OpenAPI 等来源绑定，一键重新同步 | S–M | 加一 |
| 2 | D6 | 把环境标为“生产环境”，发送前确认 | S | 加一 |
| 3 | G8 | 服务器项目的历史版本对比 | S | 不变 |
| 4 | D5 | 目录级、接口级变量 | M | 加一 |
| 5 | F6 | 本机数据保护：自动备份、撤销删除 | M | 不变 |
| 6 | F5 | 接口和目录复制 / 移动到其他项目 | S–M | 不变 |
| 7 | A6 | 响应结构校验（JSON Schema 断言） | M | 加一 |

另有 4 项可做可不做（第 4 节），2 项不建议做（第 5 节）。

工作量的记法同 0.3 那份：**S** 一两个提交、主要在 `cyberapi-core`；**M** 跨 core / service / store / 界面；**L** 要先写设计文档。改项目里保存内容的，照 CLAUDE.md 把 `cyberapi_core::version::MODEL` 加一，并顾及 `Call` / `dispatch` / `BridgeStore`、同步、备份、导出、MCP，下面不再逐项重复。

- **0.3 调研里还没转成功能的需求信号**（数字是 2026-10-25 查到的 reaction，见那份文档第 4 节）：

  - 跨集合复用请求：Postman [#1535](https://github.com/postmanlabs/postman-app-support/issues/1535)（152r）。它要的是引用，复制 / 移动只满足一部分。

- **竞品有、CyberAPI 没有的**：环境的颜色（Insomnia、Yaak）；按接口定义校验响应（Apidog 的卖点，Postman 要写脚本）。

  - `views/workspace/move_dialog.rs` 只能移到本项目的目录；跨项目只能导出再导入。
  - 树里删除只确认一次，删了就回不来；桌面版的备份要手动做；历史版本（G4）只覆盖服务器项目。0.3 第 8 节把“丢数据”列为用户最恨的事之一。
  - `versions_dialog.rs` 只列出时间、谁、多少内容，看不出那次同步改了什么。
  - `Environment` 只有名字；`FolderSettings` 只有认证、请求头和说明，没有变量。
  - 断言的对象（`assertions::Subject`）没有 Schema；OpenAPI 导入时读了请求体的 schema 用来生成示例，响应的 schema 丢掉了。

## 3. 逐项

### B7 来源绑定与一键同步（S–M）

- **做什么：** 项目记住它从哪个地址导入；项目菜单（和命令面板）的“从来源同步…”重新取回、识别格式、按 B3 的规则合并。
- **默认做法：**
  - 只记 `http(s)` 地址。文件路径因机器而异，不记；从文件或粘贴导入的项目没有这一项。
  - 来源存在 `ProjectSettings.source`，跟着项目同步：团队共用一个来源。保存项目设置时照 D3 的规矩保留其他字段。
  - 记下的时机：用“获取”从地址导入（导入为新项目或导入到已有项目）时，导入框多一个“记住来源”，默认勾选；项目已有来源时这一项写成“换成这个来源”。项目设置里可以查看、修改、清除。
  - 同步时先显示摘要：新增几个、更新几个、来源里已经没有的几个，确认后执行。合并照 B3 的“更新已有的”：只换地址、Query、请求头、请求体和类型，认证、断言、设置保留；新的放进同名目录。来源里没有了的接口**不删**，只在摘要里列出，由读者自己决定。
  - 取回经 `AppStore::fetch_text`：网页经 bridge，受“只发往公网”限制；桌面照设置走代理。要认证才能取的地址先不支持（`fetch_text` 不带认证），失败时说明原因。
  - 不定时自动同步：只在读者点击时访问网络。
  - 只有编辑者能设来源和同步，查看者看不到这一项。命令行不做。
- **落点：** core 的 `ProjectSettings.source`；状态层在 `WorkspaceState::import_again` 上加一个从来源同步的入口；界面是项目菜单、导入弹窗的勾选、项目设置弹窗。
- **实现时的补充（已完成）：** 来源不放进项目设置弹窗（那里只有认证），在“从来源同步…”弹窗里查看、改地址、“不再记住来源”；弹窗打开时就取回已记住的地址。来源连同导入到的目录一起记（`ImportSource { url, folder }`），同步时新接口进那个目录，目录删了就进顶层。合并（B3 也一样）不再写入导入后没有变化的接口，它们算作“没有改动”。网页版同样能用，只是经 bridge 取回。

### D6 生产环境标记（S）

- **做什么：** 环境可以标为“生产环境”。选中它时界面醒目，发送会改数据的请求前确认一次。
- **默认做法：**
  - 标记存在 `ProjectSettings.protected_environments`（环境 id 的列表），像 `secret_variables` 那样放在项目设置里，不改 `environments` 表；跟着项目同步。编辑者在变量弹窗里环境名旁边设置。
  - 选中时，标题栏的环境切换器用 `danger` 色并带标记。
  - 要确认的：除 GET / HEAD / OPTIONS 以外的 HTTP 请求、GraphQL 的 mutation、gRPC 调用、WebSocket 连接。不确认的：GET / HEAD / OPTIONS、GraphQL 的 query 和订阅。
  - 确认框写明环境名、方法和地址，可勾“这个项目到退出前不再询问”（只在内存里，像 `prompt()` 的回答）。
  - 运行器在这个环境里运行时，开始前确认一次。
  - MCP 的 `send_api` 在这个环境里只发不用确认的那几种，其余拒绝并说明原因：AI 不能替读者点确认。
  - 命令行不问：CI 里的环境是显式选的。复制为代码不受影响。
- **落点：** 判断“是否要确认”的规则放 core（按方法、GraphQL 操作类型）；`ApiState` 发送前和 `RunState` 开始前问；MCP 在 bridge 的 `send_api` 里拒绝。
- **实现时的补充（已完成）：** 问在请求编辑器开始发送 / 连接时（打开着的 WebSocket、gRPC 流上发消息不再问）；运行弹窗只在要运行的接口里有需要确认的时才问，问在弹窗里（不叠弹窗）。没有加颜色选择，只有“生产环境”一个标记；环境被删后留在列表里的 id 不影响任何东西，没有专门清理。

### G8 历史版本对比（S）

- **做什么：** 历史版本弹窗的每一行加“对比”，看出那个版本和现在差在哪里。
- **默认做法：**
  - 默认和服务器上现在的样子比；另可选“和它之后的那一版比”，看那次同步改了什么。
  - 按 id 列出新增、删除、改名或移动、内容改了的接口和目录，以及项目设置、变量、环境的变化；点一个改了的接口，用 `cyberapi_core::diff` 按行对比它的请求（JSON 缩进后）。
  - 对比的规则放 core，输入是两份 `ProjectConfig`，两端共用。秘密变量的值本来就不在版本里。
  - 只有服务器项目有版本，所以只在服务器项目里出现。不改数据模型、不改 bridge。
- **实现时的补充（已完成）：** “现在”取服务器上的配置，不含读者没同步的修改（弹窗里写明）。只调了顺序、没换目录的条目合成一行“有条目调整了顺序”，不逐个列。改过的接口点开后逐行对比的是整份请求的 JSON（含断言、说明、示例），只显示前 400 行。

### D5 目录级、接口级变量（M）

- **做什么：** 目录设置里加一张变量表，接口的“设置”标签里也加一张，让一组接口共用的值不必放到整个项目。
- **默认做法：**
  - 每行是名称、值、启用；值可以用模板函数。读法和运行中的值一样：`{{value(名称)}}`，也能作地址前缀 `{{名称}}`。
  - 优先级（近的胜，照 Bruno）：运行中的值（数据行、提取）> 接口的 > 目录的（内层胜外层）> 当前环境的 > 共用的。注意目录变量会盖过环境变量，所以随环境变化的值仍应写在环境里；文档里写明这一点。
  - 存为 `FolderSettings.variables` 和 `HttpRequest.variables`，跟着项目同步、导出、进备份。不能设为秘密：要保密的仍用项目的秘密变量。
  - 计算放进 `inherit::inherited`（`Sender.inherited` 已经由各发送入口填），这样运行器、命令行、MCP 自动都有。模板提示列出这些变量。
  - 导入：Bruno 的目录 / 请求变量（`vars:pre-request`）、Postman item 级的 `variable`。导出：Postman 写回 item 的 `variable`；OpenAPI 不写。
- **落点：** core（model、`inherit`、`template` 的取值顺序）；界面是目录设置弹窗和请求的“设置”标签。
- **实现时的补充（已完成）：** 和默认做法有一处不同：值**不做**模板求值，和项目的自定义变量、运行中的值一样原样使用（`{{value(…)}}` 本来就不对取到的值再求值；要算出来的值写在用它的地方）。取值顺序在 `Inherited::values`，发送前和运行中的值一起经 `run::with_values` 叠上去，所以 `{{value(名称)}}` 和地址前缀都认；地址栏的前缀选择器、模板提示也列出它们。MCP 的 `get_api` 带上接口和目录的变量（按请求头的规则打码）。OpenCollection、Hoppscotch、Insomnia 的同类字段没有读。

### F6 本机数据保护（M）

- **做什么：** 两件事：桌面版每天自动备份；树里删除接口或目录后可以撤销。
- **默认做法：**
  - **自动备份（只有桌面版）：**
    - 每天第一次启动时（或应用连续运行超过 24 小时时）在后台做一份，格式与手动备份相同（`BackupStore::snapshot` 打成 zip，能用现有的“恢复”读）。
    - 写到数据目录的 `backups/`，保留最近 7 份；库是空的时不写。
    - 设置“本地数据”里有开关（默认开）和“打开备份目录”。
    - 内容和手动备份一样：不含响应历史、Cookie、prefs，所以也不含秘密变量的值。
  - **撤销删除（两端）：**
    - 在树里删除接口或目录后，右下角的通知带“撤销”，保留 10 秒。
    - 撤销按删除前的样子放回：同样的 id、同样的位置，连同目录设置、说明、示例、断言。置顶、标签都靠 id，所以能接上。
    - 被删接口的响应历史随删除已经没了，撤销不恢复历史；通知里写明。
    - 服务器项目的副本里同样能撤销：那只是副本的修改，同步前都能撤。
    - 需要 store 能按原来的 id 放回（现在的 `TreeStore::import` 给新 id）：先在 `conformance` 里写检查，再改各后端。
  - **删除整个项目不在撤销之内。** 桌面版删除项目的确认框写明可以从自动备份恢复。
- **落点：** 自动备份在 `AppState`（复用 `back_up` 的路径）和 `paths.rs`；撤销由 `WorkspaceState` 在删除前留一份子树。

### F5 复制 / 移动到其他项目（S–M）

- **做什么：** 树的右键菜单加“复制到其他项目…”和“移动到其他项目…”，对象是接口和目录。
- **默认做法：**
  - 先选目标项目（读者能编辑的，本机和服务器的都列，可按名称或拼音搜索），再选目录（复用 `move_dialog` 的目录选择）。
  - 带过去的：请求的全部内容（认证、断言、提取、设置、说明、示例），目录的设置和其中的子项。用新的 id。
  - 移动 = 复制后删除原来的。响应历史属于读者、按接口存，**不跟过去**；移动前的确认里写明。
  - 认证是“继承”的接口到了新项目，继承那里的。请求里引用的变量在目标项目里没有时，完成后的通知列出这些名字（找引用的规则放 core）。
  - 目标是服务器项目时：桌面写进本机副本、标为未同步；网页直接写进服务器（修订号加一），读者在那个项目有没同步的草稿时，下次打开照现在的冲突规则选保留哪一份。实现时再核对一遍这条路径是否顺。
  - 仅本地的条目复制过去成为普通条目。
- **落点：** core 负责把子树转成 `ImportItem`、找出引用的变量；状态层经目标项目的 `TreeStore::import` 写入。

### A6 响应结构校验（M）

- **做什么：** 断言多一种对象“Schema”：响应体（JSON）要符合给定的 JSON Schema。
- **默认做法：**
  - 支持 draft 2020-12，`$schema` 写了 draft-07 / draft-04 时照它。只用文档里自己的 `$ref`，不取远程的（不访问网络）。
  - 断言行显示“符合 Schema”，点开在弹窗的编辑器里编辑 Schema 文本。失败时写出前 3 处不符的位置（JSON 指针）和原因。
  - 导入 OpenAPI / Swagger 时：每个操作第一个 2xx 响应里 `application/json` 的 schema（展开 `$ref`，把 3.0 的 `nullable` 等写法换成 JSON Schema）成为一条启用的 Schema 断言，标为“来自导入”。B7 同步时只更新这一条，读者自己加的断言不动。
  - 导出 OpenAPI 时，有 Schema 断言就用它作响应的 schema，代替从示例推断的。
  - 运行器、命令行（在 CI 里做契约测试）、MCP `send_api` 的断言结果自动包含它。
  - 校验库要能编译到 wasm：先试 `jsonschema` 关掉默认 feature（远程 `$ref`）能否编译到 wasm32，不能就用 `boon`。
- **落点：** core 的 `assertions`（新的 `Subject`）和 `import/openapi.rs`、`export`；界面是断言编辑器。

## 4. 可做可不做

- **F7 并排查看 / 在新窗口打开标签（M–L）：** 需求有证据（Postman #9180）。工作区的状态现在是为一个窗口设计的，要先写设计：桌面版标签右键“在新窗口打开”，新窗口只显示这一个接口的请求和响应，和主窗口共用同一个 `ApiState`。
- **A7 压测（M）：** 运行弹窗加“压测”：选一个接口，并发 1–50、按次数或时长，显示吞吐、P50 / P95 / P99、错误率，不写历史。只在桌面版提供：bridge 每个账号同时最多 16 个请求。Postman、Apidog 有，没查到投票数据。
- **B8 导入 `.http` 文件（S–M）：** VS Code REST Client、JetBrains HTTP Client 的格式：`###` 分隔请求，`@name = value` 成为共用变量，`http-client.env.json` 成为命名环境，`http-client.private.env.json` 的值作为秘密变量的值；`> {% %}` 响应处理脚本忽略并说明。用户多，但需求没查证。
- **D7 补全模板函数（S）：** `base64Decode`、`sha1`、`sha512`、`hmacSha1`、`hmacSha512`、`urlDecode`，`now` 支持偏移（如 `now(%Y-%m-%d, -1d)`）。不写脚本时，国内接口常见的签名靠这些拼。JWT 生成属于 C1，不在其中。

## 5. 不建议做

- **Vim 模式：** 要看 gpui-component 的编辑器支不支持，自己做成本太高。
- **jq：** JSONPath 过滤（#63）已经覆盖大部分用法，两套语法会让人困惑。
