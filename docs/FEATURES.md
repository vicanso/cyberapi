# Cyber API features

Everything the desktop app and the web version do; where only one of them does something, it says so. Back to the [README](../README.md).

## Native and fast

macOS, Windows and Linux, drawn on the GPU with GPUI. A project with thousands of APIs opens at once. Light and dark themes, English and Chinese, adjustable text sizes and line wrapping; the desktop window reopens where you left it, on each screen.

## Projects, folders and APIs

Search by name or pinyin, drag to reorder, duplicate, move to a folder, copy an API's config; pin the APIs you use most (⌘/Ctrl-1…9); each API you open stays open as a tab above the editor — with its edits, its responses and a request still on its way when you switch back — up to 16, the one shown longest ago closing first; close one with its button, a middle click or ⌘/Ctrl-W (the others or all from its menu), switch with Ctrl-Tab / Ctrl-Shift-Tab, and find them open again next time. New scratch request, from the project menu or the command palette, opens another tab: it uses this project's variables and environment, stays in your own settings after a restart, and is dropped when you close the tab. When you can edit the project, Save to project… picks a folder and the request becomes an API there (*0.3.1*). Group projects on the home page. ⌘/Ctrl-Enter sends, ⌘/Ctrl-N adds an API, ⌘/Ctrl-F finds an API and ⌘/Ctrl-L goes to its address, the arrow keys walk the tree, Delete and ⌘/Ctrl-D delete and duplicate there, and a list shows every shortcut. ⌘/Ctrl-K opens the command palette on any page: find an API in any project — by name, folder or method, pinyin too — and open it there, open a project, switch the environment, or run a command (new API, import, run, recent responses, settings…).

## Requests

Query, headers, auth — Basic, a bearer token, an API key in a header or the query, Digest (cameras and routers ask for it), or OAuth 2.0 with the client credentials or password grant, and on the desktop the authorization code with PKCE (an audience and a resource sent along where the server asks; the token is asked for before the request goes, kept as cookies are — yours, never in the project, its sync or a backup — and asked for again once it expires or the API answers 401, with the refresh token first when there is one; the client signs in with a Basic header or in the body; *0.3.1*: Authorize opens the system browser and listens on 127.0.0.1, the port random unless you set one, and the token is kept the same way — the web version can save that setup and says it cannot open the browser; a run, the command line and an assistant do not open one, and say to authorize in the desktop app first), its values templates, set on the API or inherited from its folder or the project — and JSON, form, multipart, XML or plain-text bodies; bulk-edit any list as text. A folder's headers go with every API in it. A query typed into the URL moves to the Query table. Timeouts, HTTP/1.1 or HTTP/2, redirects followed or not, and self-signed certificates accepted when you say so; an API can set any of these for itself in its Settings tab. On the desktop, requests go through an HTTP or SOCKS5 proxy, set in the settings or taken from `HTTP_PROXY` / `HTTPS_PROXY` / `ALL_PROXY` / `NO_PROXY`; client certificates (PEM, or PKCS#12 with its password) are presented to the hosts they are for, and authorities besides the system's — a company's own, say — trusted. The web version sends from its server, to public addresses only (*0.3.1*); a private address is refused, and the failure says why, with the same note in your language.

## GraphQL

A GraphQL body keeps the query, its variables and the operation name apart, highlighted; it is sent as JSON by a POST or as parameters by a GET, and the response's `errors` are shown above it and marked in the query where they point. Format indents the query (its comments kept) and the variables. Fetch an endpoint's schema and the query editor completes its fields, arguments and enum values; browse it — types, fields, arguments and what they are for — and click a field to put it in the query. A subscription sent over HTTP shows its results as they come, from servers that answer it as an event stream (GraphQL Yoga, graphql-sse). A GraphQL API whose address is `ws://` or `wss://` subscribes with the graphql-transport-ws protocol instead: Subscribe opens it, and each `next` or `error` shows as it comes, kept in the history when it ends. Desktop only, the same as WebSocket; an HTTP subscription is unchanged. Postman's, Insomnia's, Hoppscotch's and Bruno's GraphQL requests import as GraphQL.

## gRPC

Unary and server-streaming calls: choose gRPC as the method, give the server's address, and pick a service's method from the server's reflection or from `.proto` files (desktop). The message is JSON — with an example to start from, and template functions — and the metadata are headers; the reply comes back as JSON with its status, and a stream of replies shows as it comes, each with its time, until it ends or you stop it. An API keeps the definitions its service needs, so it is sent anywhere, the web version included, without asking the server again. Copy a call as a grpcurl command. Client-streaming and bidirectional calls connect on the desktop only: Connect opens the call, Send message sends the message in the editor (its templates run each time), a client stream's Finish sending closes the request and the one reply comes after, and a bidirectional stream sends and receives together. The conversation is kept in the history when it ends. The web version can edit those methods; a run, the command line and an AI assistant pass them by.

## WebSocket

Choose WS as the method and give a `ws://` or `wss://` address (an `http(s)://` one is taken as its WebSocket): Connect opens it with the API's query, headers, cookies and sign-in — an OAuth 2.0 token too — through the proxy and with the client certificate the host takes, as any request goes. Once open, Send message (or ⌘/Ctrl-Enter) sends the Message tab's text, its template functions run each time; what is sent and what comes show as they go, each with its time, binary messages in base64. Disconnect, or the server closing it, keeps the whole conversation in the history; a server that will not open it answers as any request. Copy one as a websocat command. Desktop only for now: the web version's server does not relay WebSockets, and a run, the command line and an AI assistant pass WebSocket APIs by.

## Server-sent events

An event stream (`text/event-stream`) shows as it comes — each event with its time, type, id and data, the one picked shown whole with the reconnection time it asked for — until the server ends it or you stop it; what came is kept in the history, as events or as it came. A language model's streamed reply, for instance.

## Variables and functions

Environment variables, custom variables and global headers per project, shared by every environment or set per named environment (dev, staging, prod…), which you switch beside the project's name — your choice alone, not your team's. Mark a variable secret (the lock in its row) and its value becomes yours alone: the project keeps only its name, so its value is never synced, exported or backed up — each teammate fills in their own (viewers too) — it shows masked, and the request the history keeps has it masked as well; an AI assistant sees only its name. Template functions such as `{{g(api, data.token)}}` (a field of another API's latest response), `{{value(name)}}`, `{{timestamp()}}`, `{{now(%Y-%m-%d)}}`, `{{uuid()}}`, `{{random(1, 100)}}`, `{{randomString(16)}}`, `{{md5(…)}}`, `{{sha256(…)}}`, `{{hmacSha256(key, data)}}`, `{{urlEncode(…)}}`, `{{base64.readFile(…)}}`, `{{readTextFile(…)}}` and `{{openFile()}}` (a file picked as you send) and `{{prompt(label)}}` (a value asked for as you send, such as a one-time code, remembered until the app quits) and `{{env(NAME)}}` (this machine's environment variable, those your shell's startup files export included; desktop), with hints while you type.

## Responses

Time split into DNS, TCP, TLS, server and transfer; the request as it went out, every header said where it came from, secrets masked till shown, and the whole exchange as `curl -v` prints it; JSON raw as it came, indented or as a tree (NDJSON too); images shown in place, fitted or zoomed, with their format and size; a PDF in the system viewer, an HTML page in your browser (desktop); any other bytes as hex; a body without a content type told by its first bytes; copy a body or save it to a file, or narrow a JSON one with a JSONPath filter kept per API; a history per API — as many responses as the settings say, 5 to 100, 10 by default — each entry with the method and path it was sent to, and picking one puts its request back; compare two of an API's responses, their bodies line by line (JSON indented, what did not change folded); and a project's recent responses, of any of its APIs, the newest 50, one picked opening its API where it was. A large body stays quick: the panel shows its start, and a line too long to wrap scrolls sideways.

## Assertions

An API's Docs tab says what it is for, in plain text (Markdown shows as written), and keeps answers as examples of what it returns — keep the response shown from the history menu, and open one there to read its body; a folder says what it is for in its settings. Both go with the project, to the team, to an AI assistant through MCP, into the Postman and OpenAPI exports (descriptions, saved responses, response examples), and come in from Postman (its saved responses too), Insomnia and OpenAPI.

Check an answer without a script: in an API's Assert tab each row checks its status, a header, a value a JSONPath finds, the body, the time it took or its size — equals, contains, matches a pattern, exists, more or less than, is of a type. Each row is checked against the response shown as you edit it, with what was found when it fails, and the status line says how many held; a click there opens the tab. An assistant that sends the API is told the same in that answer, and the history does not keep those results (*0.3.1*).

Run a folder or the whole project (its menu, Run…): the APIs go one after another in the tree's order, each send showing as it ends — its answer, how its assertions held — with a tally of what held and what failed (with no assertions, an error status fails); a send picked afterwards opens its API there. Give a data file — CSV with a header row or a JSON array of objects, pasted or (on the desktop) picked — and the APIs run once for each row, its values read as `{{value(column)}}`. Under the assertions, Extract takes a value from the answer (a JSONPath, a header, the status…) for the requests after it in the same run to read the same way: log in once, then send the token. A run's values are its own — nothing is written to the project — and what it sent is kept in each API's history as any send is. The same run goes without the window, in a terminal or CI: `cyberapi-cli run` reads a project file — CyberAPI's export or anything the app imports — prints each send as it ends, writes JUnit XML and exits non-zero when something did not hold (see [Installing](./INSTALL.md#the-command-line)).

## Cookies

Kept from every response and sent with the requests they match, across projects; search, add, edit, delete or clear them.

## cURL and imports

Paste a cURL command to make an API, copy any request as cURL, HTTPie, JavaScript `fetch`, Node.js axios, Python `requests`, PHP Guzzle, Go `net/http`, Rust reqwest, Java's `HttpClient`, C#'s `HttpClient` or Swift's `URLSession` (the menu grouped into the command line, scripting and compiled languages; following redirects and checking certificates as the settings say, Digest auth in the library's own way where it answers it; OAuth 2.0 with the token you have now, or a placeholder saying where one is had); import Postman, Insomnia, Hoppscotch (a collection, an "export all" or an environment), Bruno (a `.bru` request or environment file, or an OpenCollection YAML export), Swagger 2 / OpenAPI 3 (JSON or YAML), a HAR file from a browser's developer tools (its calls, without the images, scripts and styles a page loads, a folder for each host) and cURL into a project, or as a new project from the projects page, with how they sign in (Basic, Bearer, API key, Digest, OAuth 2.0's client credentials, password and authorization-code grants, *0.3.1*) and their environments (a Postman or Hoppscotch environment file, Insomnia's sub-environments or an OpenCollection's environments as named environments; Bruno's `{{process.env.NAME}}` as `{{env(NAME)}}`; an OpenAPI document's security schemes as the project's auth, values for you to fill) — pasted, from a file, or fetched from an address (the web version's through its server, where requests may go); importing again adds only what is new — into the folders of the same name — or also updates the APIs the project has, the same method to the same path, keeping how they sign in, their assertions and settings; export an API, a folder or a project — a folder or a project also as a Postman collection (v2.1) or an OpenAPI 3 document (YAML: the address's variable as its servers, bodies as examples with a schema read off them, how they sign in but never the values — OAuth 2.0 as its flow, token URL and scopes, and for the authorization code its authorization URL and loopback callback, *0.3.1*).

## Mock server

On the desktop, a project answers as a mock server from its APIs' examples: **Mock server…** in the project menu starts it on this machine (port 4010 unless you choose another). A request goes to the API of its method and path — the address without its variable, scheme and host; `{{id}}`, `:id` or `{id}` match any segment, and the more fixed segments win — and gets the API's first example, or the one an `x-mock-example` header names; one with no example, or no API, answers 404 saying why. Any origin may call it (CORS preflights are answered), it follows the project as you change it, and the dialog lists the requests it answered. It runs while the project is open.

## Your data

Back up and restore on the desktop, in the same format as the earlier Tauri app.

## Teams

A self-hosted web version — one binary or a Docker image, at the root or under a sub-path — with accounts by invitation, teams, and per-project roles (viewer, editor, manager); share a project with accounts or teams, or move it to another team. The desktop app signs in to the same server — listing the team's projects as they come — uploads a project of its own there, keeping its history, and works on shared projects offline, syncing when you choose and asking whose version to keep when someone else changed it meanwhile; APIs and folders can stay local, out of the sync. The server keeps a project's last 50 versions — what it was before each sync — and an editor puts one back from the project menu (Versions…); what it replaces is kept too, so that can be undone.

## AI assistants

The web version is also an MCP server: Claude Code, Cursor or another MCP client signs in with a token you issue and reads your projects, APIs, variables and responses, with secrets masked; a token you allow to may also send saved APIs — and when the API checks its answers, that reply lists each check and, where one failed, what was found; those results are not kept in the history (*0.3.1*) — and one you allow to change may make and change APIs (never delete them) where your account edits.
