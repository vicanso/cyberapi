# 服务器项目同步与邀请注册

> 状态：待实现。产品选择已确认，本文是功能说明。与 [architecture.md](./architecture.md) 里已经落地的行为冲突时，落地前以本文为准，落地时再把架构文档改过来。
>
> 进度：第 1 步已完成（`TreeStore::config` / `replace`，`cyberapi_core::sync::ProjectConfig`）；第 2 步已完成（`cyberapi_core::sync::step`：除文中四种结果外，另有“已是最新”和“推送写入”两种，调用方不必再自己比较修订号）；第 3 步已完成（网页的工作副本是编译到 wasm 的 `MemoryStore`，见 `states/copy.rs`；草稿在 `drafts_local.rs`；项目名称和说明在首页卡片上修改，同样进草稿）；第 4 步已完成（`invites` 表；`DirectoryStore::invites` / `create_invite` / `revoke_invite`，管理员不再直接建号；`POST /v1/invite` 查看、`POST /v1/invite/accept` 接受；链接是页面地址加 `#invite=<令牌>`，登录页显示注册表单；接受时按当时的身份再检查一次发出者）。

桌面版和网页版打开的是同一类项目，但项目有两种来源。桌面可以同时拥有只在本机的项目，和登录后从服务器拿来的项目。网页版只有服务器项目。

服务器对桌面只负责项目配置的同步。发请求、响应历史、Cookie、界面状态仍走本机库。配置改完不自动上传，用户按项目点同步才写入服务器。账号不能自行注册，要拿邀请链接来建。

## 1. 两种项目

| | 本地项目 | 服务器项目 |
|---|---|---|
| 谁能有 | 只有桌面 | 桌面和网页 |
| 存在哪 | 本机 SQLite | 服务器一份；桌面另有本机副本；网页的未同步修改在该浏览器里 |
| 要不要登录 | 不要 | 要。桌面在设置里填写这一台 bridge 的地址并登录 |
| 权限 | 使用这台电脑的人可以改全部 | 沿用现在的 `Viewer` / `Editor` / `Manager` |
| 同步 | 没有同步 | 按项目拉取和同步 |

桌面未登录时只显示本地项目。服务器项目的副本留在本机，按账号分开，换账号或退出后不再显示。本地项目不受登录影响。

一台桌面只配置一个服务器地址。地址和登录会话放在数据目录的单独文件里，不写进项目库，也不进备份。

这一版不做「把本地项目上传成服务器项目」，也不做「把服务器项目摘成纯本地项目」。两边的 id 不必互相迁移。

## 2. 什么走服务器，什么留在本地

同步的是一份项目配置：

- 项目名称和说明
- 目录、接口、目录里的顺序、顶层顺序
- 变量：环境变量、自定义变量、全局请求头

下面这些不进同步。桌面即使登录了服务器，也继续写本机库：

| 内容 | 桌面（含服务器项目） | 网页 |
|---|---|---|
| 发请求 | 本机直接发 | 仍由 bridge 代发 |
| 响应历史 | 本机 `responses`。`g()` / `get()` 读这份 | 服务器上该账号自己的历史，发送时立即写入 |
| Cookie | 本机 | 服务器上该账号自己的，立即写入 |
| 主题、语言、超时、分栏、窗口、每块屏幕的位置 | 本机 | 仍立即写入该账号的 `prefs` |
| 展开、选中、活动标签 | 本机 | 仍立即写入该账号的工作区 `prefs` |
| 固定接口、JSON 默认是文本还是树 | 本机文件 | 浏览器 `localStorage` |

同一个人在桌面和网页各发一次，两边的历史互不可见。桌面的 `{{g(接口 id, token)}}` 只用这台电脑上该接口的最新响应。

授权、成员、邀请、停用账号、重置密码、转移项目归属，都不是项目副本，操作后立即生效，不等同步。

新建服务器项目立即写到服务器：它要先有 id 和所属团队，别人才能被授权。建好后是空项目，桌面再拉一份副本。里面的目录、接口和变量从这一刻起进入第 3 节的同步。新建本地项目与现在相同，不接触服务器。

删除服务器项目立即作用在服务器上，并删掉本机副本。若该项目还有未同步的修改，确认框要写明这些修改会丢掉。删除项目里的某个目录或接口只改本地副本，随下一次同步上传。

## 3. 同步

单位是一个项目。每个服务器项目各自记住「上次与服务器对齐时的 `revision`」，称为基准。

### 3.1 拉取

登录成功，以及打开一个服务器项目时：

- 本地没有未同步修改：用服务器的当前内容替换副本，基准改成服务器的 `revision`。
- 已有未同步修改：不替换。提示这份修改还没上传。若此时服务器的 `revision` 已经不是基准，同时提示服务器上也有更新，仍然不覆盖本地。
- 拉不下来（断网、未登录、没有权限）：桌面继续用本机副本，并提示没拉到。网页没有副本时只能看上次留在这个浏览器里的草稿；草稿也没有就报错。

项目打开期间沿用现在的修订号检查。没有未同步修改时，发现服务器变了就拉取并刷新树和变量。有未同步修改时只更新「服务器上有更新」的提示，不重载正在看的内容。

### 3.2 修改

`Editor` 及以上对项目配置的修改写入本地副本（网页写入第 4 节的草稿），并把该项目标成未同步。不向服务器提交。

查看者与现在一样不能改。查看者没有未同步状态，也没有同步按钮。

不在每次按键时弹窗。项目卡片和工作区保持「未同步」。这一次打开里第一次改动时提示一次。

发送用的是当前屏幕上的这份配置，包含还没同步的修改。桌面因此可以先在本机把请求跑通，再决定上传。

### 3.3 同步（推上服务器）

按钮在该项目的卡片上和工作区里。一次只推这一个项目，内容是整份项目配置（第 2 节列出的那些），在服务器的一个事务里替换。

- 服务器的 `revision` 仍等于基准：写入，修订号加一，基准改成新值，清除未同步。
- 服务器的 `revision` 已经变了：不写入，弹出选择：
  - **用本地覆盖服务器**：仍用本地这份整份覆盖，然后把基准改成新修订号。
  - **改用服务器上的版本**：丢掉本地未同步的修改，改成服务器的当前内容，清除未同步。
  - **取消**：两边都不动。
- 推送时权限已经不够：不写入，未同步的修改留着，并说明原因。
- 推不上去：未同步的修改留着。

另有「放弃本地修改」：重新拉取服务器的当前内容并清除未同步。拉不下来时不动本地。

新建的目录、接口、变量在本地就生成 id，同步后服务器使用同一个 id。

## 4. 网页上的未同步修改

网页没有 SQLite。某个服务器项目的未同步修改写在这个浏览器里，按账号 id 和项目 id 分开，刷新之后还在。同步成功后删掉这份草稿。

换一个浏览器、换一台电脑，看不到没同步的修改。同一浏览器里的两个标签共用这一份；后保存的草稿盖住先保存的，仍然不会因此上传。

浏览器存不下这份草稿时，修改只留在当前页面，并提示刷新后会丢失。

## 5. 邀请注册

第一个管理员仍用一次性 setup token 创建。此后不能自己注册，也不能再由管理员填写初始密码直接建号。管理员重置密码、停用账号的能力保留。

邀请是一条一次性链接，管理员复制出去，程序不代发邮件。默认 7 天内有效，用过即废，发出的人可以在过期前撤销。接受邀请在网页完成；桌面只登录已经建好的账号。

| 谁来邀请 | 邀请结果 | 能给的角色 |
|---|---|---|
| 系统管理员 | 新账号和他自己的个人空间，不加入其他团队 | 无团队角色 |
| 团队 `Owner` | 新账号，并进入该团队 | `Member`、`Admin`、`Owner` |
| 团队 `Admin` | 新账号，并进入该团队 | `Member`、`Admin` |

个人空间不能邀请别人加入。被邀请人自己填写用户名、显示名和密码，规则与现在的账号名、密码规则相同。用户名已被占用、邀请过期、已使用或已撤销时，账号不会被创建。

团队邀请遵守现在的成员规则：只有 `Owner` 能邀请出另一位 `Owner`。

## 6. 分步

每一步做完，已经存在的本地项目都保持现在的行为：立即写入本机库，没有同步按钮。网页在第 3 步完成之前仍立即保存。存储先写会失败的检查，再改各后端。邀请不依赖草稿，可以和第 3 步并行。

### 第 1 步：整份项目的读取和按修订号替换

只动存储，没有界面。

在 `cyberapi-core` 增加一份项目配置的形状：名称、说明、目录、接口、顶层顺序、三类变量。在 `TreeStore` 增加两件事：读出一个项目的这份配置；用一份配置替换该项目。替换在一个事务里完成，目录、接口、变量的 id 原样保留，由调用方生成。`revision` 必须等于调用方带来的基准才写入，写完加一；对不上就拒绝，一份都不改。另有一次强制替换，给「用本地覆盖服务器」用。历史、Cookie、`prefs` 不动。

`MemoryStore`、`TursoStore`、`SqlStore` 都实现。检查放进 `conformance`：基准相符则替换、基准过期则拒绝且内容不变、强制替换成功、查看者拒绝、编辑者可以、历史还在。先故意改坏 `MemoryStore`，确认检查会失败。`Call`、`dispatch`、`BridgeStore` 同时加上。改 SQL 时跑 `make test-sql`。

这一步不改现有的逐条 `create` / `save_request`。本地项目继续走那些方法。

### 第 2 步：同步该怎么做，做成纯函数

仍不改界面。函数放在 `cyberapi-core`，输入是基准修订号、服务器现在的修订号、本地有没有未同步修改，输出只有四种：拉取并替换、保持本地并提示未同步、保持本地并同时提示服务器也有更新、推送时发生冲突。断网不在这个函数里。

单测覆盖第 3 节的每种组合。后面的界面只调用它，不再各自判断。

### 第 3 步：网页改为草稿，并做出同步

这一步做完，网页侧的同步就齐了。桌面仍走原来的立即保存。

服务器项目的编辑不再调用树、请求、变量的存储方法，改写入草稿。草稿记在这个浏览器里，键按账号 id 和项目 id 分开，写法跟 `pins_local` 一样；同步成功或放弃后删掉。发送、历史、Cookie、主题、工作区展开和选中仍立即写服务器，读的是屏幕上这份草稿（含未同步的修改）。

打开项目、登录后、以及现在的修订号轮询，都先走第 2 步的函数。该拉取才替换内存和草稿基准。查看者不能改，不出现未同步，也没有同步按钮。

界面：项目卡片和工作区显示「未同步」；第一次改动提示一次，不在每次按键弹窗；同步、冲突时的三个选择、放弃本地修改。文案补进 en、zh-CN、uk。新建目录、接口、变量的 id 在草稿里生成，随同步带上。

网页的新建项目、删除项目、授权和成员仍立即请求服务器。删除时若有草稿，确认框说明会丢掉。

验收：`make lint`、`make check-web`，以及在浏览器里走通编辑后不上传、刷新还在、同步成功、两边都改过时弹出选择、查看者没有同步。这一步完成前不要把网页交给会改配置的人用。

### 第 4 步：邀请注册

可与第 3 步并行。

`invites` 表只追加迁移：令牌哈希、邀请人、可选的团队和角色、过期时间、撤销。`DirectoryStore` 增加创建、列出、撤销、接受。接受是未登录即可调用的 bridge 路由，在网页的登录页完成；建号和个人空间仍用现在的事务，团队邀请再按上面的角色表写入成员。系统管理员的账号弹窗改为生成并复制链接，不再填写初始密码。重置密码和停用保留。

检查：过期、已用、已撤销、用户名占用都不建号；`Admin` 邀请不出 `Owner`；个人空间拒绝邀请；非管理者拒绝创建。桥的测试覆盖接受和撤销。

### 第 5 步：桌面登录这一台 bridge

设置里填写一个服务器地址，并登录、退出。会话令牌放在数据目录的单独文件，不进 SQLite，也不进备份。bridge 的登录在现有 Cookie 之外，让桌面能拿到并送回同一枚令牌。未登录时首页与现在相同。

这一步只证明登录态。还不把服务器项目画出来，也不从服务器拉配置。

### 第 6 步：桌面的服务器项目

这一步做完，桌面侧的同步就齐了。

本机库追加一张绑定：账号、项目 id、基准修订号、是否未同步。服务器项目的目录、接口和变量放进现有的表，这样本机的发送、历史和 Cookie 不用第二条路径。首页在登录后同时列出本地项目和该账号的服务器项目；退出或换账号后服务器项目不显示，副本不删。本地项目没有这张绑定。

编辑服务器项目只写本机副本并标未同步，不调用 bridge 的逐条写入。拉取、轮询、同步、冲突和放弃，复用第 2 步的函数和第 3 步的界面。桌面只对服务器项目轮询修订号，本地项目不轮询。发送仍用本机引擎；历史和 Cookie 只写本机。同步不上传它们。

新建服务器项目立即在服务器创建，再拉空副本。删除立即删服务器，并删掉本机副本和绑定。现有备份会带上这些副本；恢复只恢复本机，不自动推送。

验收：`make lint`、`make check-web`、`make test-sql`。本地项目一条同步相关的请求都不发。服务器项目断网时仍可编辑和发送，历史留在本机。

## 7. 这一版明确不做

- 本地项目与服务器项目互转。
- 一台桌面连接多个服务器。
- 按接口合并冲突。冲突时只能整份选用本地，或整份改用服务器。
- 把桌面的历史、Cookie、设置上传到服务器。
- 用邮件发送邀请。
